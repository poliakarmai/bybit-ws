# PRD: One-Click Trading для bybit-ws

> Версия: 1.0 | 2026-07-31 | Статус: драфт

## Цель

Добавить в Telegram-бота GridSignal возможность входа в позицию по одной кнопке
на аккаунте bybit-ws. Сетап → кнопка «Взять» → позиция открыта с умным SL/TP.

## Архитектура

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  Telegram-бот    │     │   RPC (:8766)    │     │   Bybit API      │
│  gridsignal-bot  │────▶│                  │────▶│                  │
│                  │     │  POST /position  │     │  place_order()   │
│  /scan → кнопки  │     │  POST /close_pos │     │  set_sl/tp()     │
│  /position → live│     │  GET  /calc_qty  │     │                  │
│  /setrisk → conf │     │                  │     │                  │
└──────────────────┘     └──────────────────┘     └──────────────────┘
         │                        │
         ▼                        ▼
┌──────────────────┐     ┌──────────────────┐
│  user_risk.db    │     │  state.db        │
│  (настройки)     │     │  unified_sl.py   │
│  - risk_pct      │     │  auto_tp.py      │
│  - leverage      │     │  (автоматически) │
│  - margin_mode   │     │                  │
└──────────────────┘     └──────────────────┘
```

Поток: бот нажимает «Взять SOL LONG» → RPC `/calc_qty` считает размер →
RPC `/position` открывает позицию с SL/TP → unified_sl подхватывает и ведёт SL →
бот показывает live-позицию с PnL.

## Требования

### Функциональные

- [ ] **REQ-01:** Кнопка «Взять» под каждым сигналом `/scan` (inline-кнопка)
- [ ] **REQ-02:** Расчёт размера позиции: `qty = (balance × risk_pct) / (entry / leverage)`
- [ ] **REQ-03:** `/setrisk` — настройки: % риска от депо, плечо, кросс/изол
- [ ] **REQ-04:** При входе — немедленная установка SL и TP через unified_sl
- [ ] **REQ-05:** Кнопка «Мои позиции» — live PnL, %, SL, TP для каждой
- [ ] **REQ-06:** Кнопка «Закрыть» рядом с каждой позицией
- [ ] **REQ-07:** Подтверждение перед входом (модалка: «Взять SOL LONG $50? SL=XX, TP=YY»)
- [ ] **REQ-08:** Защита: только для admin ID (319665243), не для обычных юзеров

### Нефункциональные

- [ ] **NFR-01:** Безопасность — токен RPC никогда не попадает в ответ бота
- [ ] **NFR-02:** Отказоустойчивость — если bybit-ws не в сети, бот показывает ошибку, а не падает
- [ ] **NFR-03:** Производительность — ответ на кнопку < 5 секунд

## Данные

### Новая таблица: `user_risk` (SQLite в `~/.local/share/gridsignal-bot/users.db`)

```sql
CREATE TABLE IF NOT EXISTS user_risk (
    user_id INTEGER PRIMARY KEY,
    risk_pct REAL DEFAULT 5.0,      -- % от депо на сделку
    leverage INTEGER DEFAULT 3,      -- плечо
    margin_mode TEXT DEFAULT 'isolated',  -- isolated | cross
    max_positions INTEGER DEFAULT 5, -- макс. открытых позиций
    updated_at TEXT
);
```

### Новые RPC-эндпоинты (в `rpc.py`)

| Эндпоинт | Метод | Назначение |
|----------|-------|-----------|
| `/calc_qty` | POST | `{symbol, risk_pct, leverage}` → `{qty, min_qty, available}` |
| `/close_position` | POST | `{symbol}` → закрыть позицию по рынку |
| `/position_detail` | GET | `?symbol=X` → полная инфа по позиции (SL, TP, PnL%) |

### Существующие RPC (уже есть)

| Эндпоинт | Использование |
|----------|--------------|
| `/scan` | Сетапы для кнопок «Взять» |
| `/position` | Вход в позицию (place_entry) |
| `/positions` | Live-отображение всех позиций |
| `/balance` | Расчёт размера позиции |

## Не делаем (out of scope)

- ❌ One-click на чужих аккаунтах (хранение API-ключей)
- ❌ Красивый скрин позиции (фаза 2)
- ❌ MiniApp (фаза 3)
- ❌ Авто-вход по сигналу без подтверждения (опасно)
- ❌ DCA / добивка через кнопку

## Изоляция от авто-стратегий

**Ключевой принцип: one-click позиции = авто-позиции, только вход ручной.**

В отличие от pump-позиций (флаг `"manual": true` в pumps.json, unified_sl их пропускает),
one-click позиции НЕ помечаются как manual. Они попадают в общий цикл:

| Модуль | Поведение для one-click | Защита от конфликта |
|--------|------------------------|---------------------|
| **unified_sl.py** | ✅ Работает (tight → simple → hard → BE) | Без флага manual — не пропускается |
| **auto_tp.py** | ✅ Работает (ATR-based 1×/2×/3×) | Уже проверяет is_manual_position (стр. 146) |
| **auto_entry.py** | ⛔ Не войдёт повторно | Видит позицию в state.db → скипает символ |
| **auto_short.py** | ⛔ Не войдёт повторно | Видит позицию в state.db → скипает символ |
| **risk_manager.py** | ✅ Считает в лимитах | Все позиции в общем пуле max_positions |
| **main_async.py** | ✅ В общем цикле | Не отличает one-click от авто |

**Что произойдёт при сценариях:**

1. **«Взял SOL через кнопку, авто сканит SOL»** → авто видит что SOL уже в позиции → скипает.
2. **«Авто открыл ATOM, потом нажал Взять ATOM»** → `/position` вернёт ошибку «уже в позиции».
3. **«Закрыл one-click позицию, авто сканит»** → позиция удалена из state.db → авто может войти заново (нормально).
4. **«Circuit breaker сработал»** → one-click тоже блокируется (`/position` проверяет CB).

## Риски

| Риск | Вер. | Влияние | Митигация |
|------|------|---------|-----------|
| Ошибка расчёта qty | Низ. | Выс. | Тесты на граничные случаи |
| RPC недоступен — бот падает | Низ. | Сред. | try/except + сообщение юзеру |
| Случайный вход не по тому символу | Сред. | Сред. | Подтверждение с символом/ценой/SL |
| One-click позиция открыта, но SL не встал | Низ. | Выс. | Проверка SL после входа, повторная попытка |
| Двойной вход (one-click + авто одновременно) | Низ. | Сред. | state.db — SSOT, авто проверяет перед входом |

## Критерии приёмки

- [ ] AC-01: Кнопка «Взять» появляется под сигналами `/scan` только для админа
- [ ] AC-02: Нажатие → сообщение «Взять SOL LONG на $50? SL=XX, TP=YY» с кнопками «Да»/«Нет»
- [ ] AC-03: «Да» → позиция открыта, SL/TP выставлены, unified_sl подхватывает
- [ ] AC-04: `/position` показывает все позиции с PnL, %, кнопкой «Закрыть»
- [ ] AC-05: «Закрыть» → позиция закрыта по рынку, показывается PnL сделки
- [ ] AC-06: Все smoke-тесты проходят (52 теста)
- [ ] AC-07: Нет регрессии в существующем функционале бота
